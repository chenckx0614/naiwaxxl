# 奶蛙消消乐（Match-3）

纯前端三消小游戏，单文件 `index.html` + 图片/音频资源，无框架、无构建步骤，直接用浏览器打开即可游玩。

## 目录结构

```
index.html          游戏本体（HTML + CSS + JS 全部内联）
minitool/           小红书小工具打包版（脚本外置，兼容 Chrome 61，无音频文件）
icons/              底部道具栏图标（Fluent Emoji 3D 转出的 WebP）
naiwa/
  1/                第一关的棋子素材（a~i.png，当前取 b/d/f/g/i 五种）
bgm/
  bgm.mp3           背景音乐（循环）
  combo1~5.mp3       消除成功音效（每次随机播放一个）
  end.mp3            通关结算音效
```

## 视觉素材来源

底部道具栏（立体圆钮 + 数量徽章 + 按下下沉）造型借鉴 Uiverse.io 社区的拟物/新拟态圆形按钮，
组件源码在开源镜像仓库 [uiverse-io/galaxy](https://github.com/uiverse-io/galaxy)（MIT）。

道具图标取自 [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji)（MIT）的 **3D** 版本：
Hammer / Firecracker / Cyclone / Glowing star，用 ffmpeg 转成 128px WebP（`icons/hammer.webp`、`bomb.webp`、
`shuffle.webp`、`moves.webp`，文件名按功能命名，与素材本身解耦）。同一套 3D 渲染风格，保证
Windows / iOS / Android 各端图标渲染一致（系统 emoji 字体差异较大）。

## 多语言（简体中文 / English）

游戏内「设置 → 其他设置 → 语言」点 中文 / English 即时切换整个界面——开始页、顶栏（步数/目标/分数）、
道具说明、设置项、关卡面板、作者面板、结算面板与 toast 提示全部跟着变。选择记在 `localStorage`
（键 `naiwa-xxl-lang-v1`），下次打开还是上次那档。

加文案只改一处：

- 静态文案在 HTML 上标 `data-i18n="key"`（标题用 `data-i18n-title`，图片描述用 `data-i18n-alt`）；
- 脚本里的动态文案统一走 `T('key', { n:3 })`，`{n}` / `{s}` 是占位符；
- 中英文两套词条都在 `index.html`（小工具版在 `minitool/app.js`）顶部的 `I18N` 表里，缺词条自动回退中文。

英文文案比中文宽，样式里用 `html[lang="en"]` 逐处收了一档字号/字距（开始按钮、副标题、弹窗标题等），
避免窄屏溢出。游戏 LOGO「奶蛙消消乐」是品牌字，两种语言下都保留中文。

## 玩法

- **滑动**任意棋子往上下左右：按住时棋子跟着手指走，越过约 1/3 格即判定交换；
  没越过会弹回原格并当作点按。能凑成三个及以上同类会消除，凑不成就自动弹回
- 也可以**点选**两个相邻棋子完成交换
- 在限定步数内收集完顶部目标即为过关，剩余步数越多星级越高
- 底部四个道具：小锤（敲掉单格）、炸药（炸 3×3）、旋风（重排棋盘）、星星（加 5 步）
- **计分**：每消除一格 10 分，连锁第 n 段 ×n 倍率（道具消除不吃倍率）。分数实时显示在顶栏，
  每关最好成绩记进存档，结算面板显示「本局 N 分 · 最高 N 分」
- **复活**：步数用完时可在结算面板花一次机会「复活 +5 步」继续本局，棋盘、分数、目标进度全部保留。
  **每局限一次**，用掉之后再失败就只剩「重新开始」
- 棋盘与道具栏在视口内整体垂直居中；内容比视口高时自动退化为从顶部排列，不会裁掉顶部

## 手感与反馈

- **消除粒子**：棋子消除时先回弹放大再旋转收缩，同时喷出 4 片同色碎片飞散淡出。
  粒子走 Web Animations 的显式关键帧（`el.animate([{from},{to}])`），和下落动画同一套机制。
  ⚠️ 这里刻意**不写 `will-change: transform` / `transition`**：`will-change` 会把动画提升到
  合成器线程，而新建图层那一帧可能拿不到起始位置快照，动画会从棋盘左上角飞出来——下落偏移那个
  老 bug 的根因就是它，别再加回去。
- 粒子回收有两条路：动画正常结束由 `onfinish` 回收；页面切到后台时 Web Animations 会整体暂停、
  `onfinish` 迟迟不来，所以另挂一个 `setTimeout` 兜底，保证节点不堆积。
- **震动反馈**：`navigator.vibrate`，交换 10ms、消消除 12ms（连锁 22ms）、无效 30ms、通关/失败用序列。
  iOS Safari 没有这个 API，受限 WebView 也可能禁用，所以整个调用包在 try 里静默失败，震不了不影响游戏。
  可在「设置 → 游戏设置 → 震动」关掉。
- **消除与下落重叠（消除完不再"卡一下"）**：旧实现是三拍严格串行——被消除的棋子先播完 280ms 的 pop
  收缩动画 → 元素从 DOM 移除 → 上方棋子才开始下落。问题是 pop 播到 200ms 左右棋子其实已经看不见了，
  屏幕上却还有 80ms 谁也不动；接着下落用的又是起步最慢的 `ease`，这两段合起来就是主观上的「卡一下」。
  现在标记消除的同时就把格子数据清空、110ms 后上方即开始下落（`DROP_LEAD_MS`），被消除的棋子留在原地
  把 200ms 的 pop 播完再由定时器收走——收缩与下落重叠在同一段时间里，屏幕上始终有东西在动。
  `POP_MS` 与 CSS 里 `.tile.clearing .face` 的动画时长是同一个值，改一个必须改另一个。
- **下落时长按落差给**：旧实现固定 220ms，掉 1 格像慢动作、掉 4 格像瞬移。
  现在 `dropDur(rows, k) = min(380, 130 + rows × 44) × k`，整列共用同一时长（起止一致，堆叠间距才不会散）。
  位移曲线也从 `ease` 换成 `cubic-bezier(.22,.9,.28,1)`——`ease` 最慢的一段恰好是起步，
  「开始下落」的第一印象因此是"没动"。
- **不做无谓的强制同步布局**：`readTranslate` 只在棋子上真有动画在跑时才去问渲染层要实时位置。
  静止棋子的位移直接用逻辑位置——`getComputedStyle` 会强制浏览器 flush 掉所有待处理的样式变更，
  一轮下落里问十几次就是十几次强制同步布局。
- **同一枚棋子只留一段位移动画**：`TILE_ANIM`（WeakMap）记着当前动画，新的顶掉旧的，
  避免两段叠着算、合成器上的动画对象越堆越多。
- **连锁加速**：连得越深落得越快——第 1 段 1.0 倍，之后每段递减 15%，最快 0.55 倍（`dropSpeed`）。
  `dropDur` 的 `k` 就是它，等待时间同步缩短，连锁才有节奏感。
- **得分飘字**：每处消除在棋子重心弹一个 `+N`。外层 `.score-float` 只负责居中定位，
  内层 `<span>` 负责位移淡出——分开是为了让动画的 `transform` 不覆盖居中用的 `transform`。
- 粒子、飘字、分数弹跳都受「设置 → 游戏设置 → 关卡动画」开关控制，关掉后走快速路径（不生成粒子）。

## 音量与容错

- **必须点一下才出声（浏览器规则，非 bug）**：Chrome / Safari / 各家 WebView 都有自动播放策略——
  用户手势之前音频一律不准出声（`AudioContext` 恒为 `suspended`，`<audio>.play()` 直接抛
  `NotAllowedError`），所以**打开页面自动放 BGM 在网页上做不到**。这里的做法是：上下文提前建好并
  预解码音效（建的时候不受限，只是被冻住），同时挂上 `pointerdown / touchend / click / keydown`
  四种事件，任意一种第一次触发就解锁，音乐立刻响起——所以表现为「点一下就开始放」。
  `resume()` 是异步的，音序器会在 promise 落地、上下文真的 `running` 之后才启动
  （被冻住时不空转，音乐也从第一步开始而不是从半句接上）。
- **音量**：设置里「背景音乐」「音效」两行各带一个滑块，与开关同行（开关管启用/禁用，滑块管音量）。
  存储键 `naiwa-xxl-vol-v1`。两条音频链的基准值不同——小工具版是 WebAudio 合成（BGM 0.16 / 音效 0.5），
  线上版是 mp3 文件（BGM 0.5 / 音效 0.5 / combo 0.7 / 结算 0.8），所以音量按各链基准分别换算，
  滑到 100 就是加音量功能之前的音量。
- **运行时错误兜底**：`window.onerror` + `unhandledrejection` 会在底部弹一条可点的红条，点一下重载页面。
  只提示一次（避免连锁错误刷屏），出错原因留在 `window.__xxlLastError` 方便真机排查。
- **切后台自愈**：Web Animations 在页面切到后台时会整体暂停，若正好卡在动画中间，`busy` 会一直锁着输入、
  回来点哪都没反应。回到前台时会检查一次——没有正在跑的动画就解锁并校正棋盘位置。
- **弹窗高度**：设置面板在小屏上可能比视口高，所以 `.overlay` 可纵向滚动、上边留出面板标题的位置，
  `.panel` 用 `margin:auto` 居中——矮内容居中，高内容从顶部排列可滚，顶部标题和底部按钮都不会被裁。

## 关卡与进度

关卡集中在 `index.html`（小工具版在 `minitool/app.js`）里的 `LEVELS` 表，**加新关卡只改这一处**：

```js
const LEVELS = [
  {
    no: 1,                  // 关卡号，同时是素材目录名（naiwa/1/）
    moves: 25,              // 步数
    needs: [15, 12, 10],    // 三个目标各需消除的数量
    types: [                // 该关的消除图标
      { key:'b', img:'naiwa/1/b.png', color:'#7ec3f5' },
      // ...
    ],
  },
  // 第 2 关做好后往这里追加一条即可
];
```

- 关卡选择面板会按 `LEVEL_SLOTS`（默认 9）铺格子；`LEVELS` 里没有的编号自动渲染成「敬请期待」的锁定格，
  所以追加关卡后锁定格会自动减少，不用改 UI。
- 进度存在 `localStorage`（键 `naiwa-xxl-progress-v1`）：`unlocked` = 已解锁到第几关（开始页的「当前进度」），
  `stars` = 每关最好星级，`best` = 每关最高分（开始页显示所有关卡里最高的那次）。
  localStorage 不可用时（隐私模式）自动降级为仅本次会话有效，不影响游玩。
- 通关最后一关后，结算面板的按钮会从「下一关」变成「返回首页」。

## 换关卡素材

素材按 `naiwa/<关卡号>/` 分目录，在 `LEVELS` 里对应那一关的 `types` 数组中引用：

```js
types: [
  { key:'b', img:'naiwa/2/b.png', color:'#7ec3f5' },
  // ... 换成新关卡图片路径
]
```

棋盘棋子、顶部目标图标、关卡面板都会自动跟随更新。

## 本地运行

直接双击 `index.html` 即可。若浏览器因本地文件协议限制音频播放，用本地服务器打开：

```bash
python -m http.server 8000
# 然后访问 http://localhost:8000
```

> 注意：浏览器有自动播放策略，通常需要用户先点击页面后才会有声音，这是浏览器限制，非代码问题。
